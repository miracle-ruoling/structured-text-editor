# 结构化文档编辑器：实施计划

更新时间：2026-10-19。状态：设计完成，开始阶段 1。产品暂名「文序」。

## 1. 用户目标与协作约定

用户希望文档对象具有明确可见、可手动修改的类别与标签；自由组合类别、标签、所在结构等条件筛选对象，再执行格式调整或其他操作。必须能交付 Word 文件，长期支持日常写作。

- 分阶段交付，每完成一个阶段停下，由用户检查效果，再继续下一阶段。
- 实施前写计划，重要决策、完成情况和已知边界持续记录，供后续会话恢复。
- 代码与参考项目 copyQ 解耦，绝不修改参考项目。
- 使用 Git 保存可运行里程碑；不自动推送远程。
- 环境故障最多进行一次有针对性的重试；仍无法解决时向用户说明，不自行反复更换环境或绕路。
- 界面以中文为主，现代、克制、稳定；避免把所有属性一次堆满。

## 2. 产品路线

长期：结构化文档模型 + 编辑器 + DOCX 等格式适配器。

阶段 1：先做已有 DOCX 的结构标注与批量格式工作台。源 DOCX 是内容权威来源，类别、标签、格式覆盖是独立项目状态；导出时针对原包修改，避免通过 Markdown 中转而丢失内容。

阶段 3 才引入原生内容编辑。已有 DOCX 的保真修改模式，与原生文档的编辑/转换模式应明确区分，不能承诺任意复杂 DOCX 无损往返。

## 3. 技术路线

- 前端：React + TypeScript + Vite；原生 CSS 设计变量，Lucide 图标。暂不引入重型组件框架。
- 后端：Python 3.13 + FastAPI + Pydantic + lxml；uv 管理项目虚拟环境与锁文件。
- 运行：单机本地服务，仅绑定 127.0.0.1；构建后的前端由同一服务提供。无需 Office、Pandoc 或云服务。
- DOCX：zipfile 读取包，lxml 定点修改 OOXML；不重建媒体、关系、页眉页脚等未修改文件。
- 存储：项目目录内 data/，原 DOCX 与版本化 JSON 分离、JSON 原子替换。提供便携 .sdoc 项目包导入/导出。
- 验证：pytest 验证筛选、撤销、保存、Word 包完整性和修改范围；TypeScript 编译；真实浏览器检查主要流程和界面。
- 后续编辑器候选：ProseMirror / Tiptap。阶段 1 不引入内容编辑依赖。

选择 Web 界面是为了稳定实现筛选器、对象标记和属性检查，并为将来的富文本编辑铺路。桌面封装后置，不在首版引入 Electron/Tauri 打包负担。

## 4. 核心模型与职责

### 对象

- kind：结构类型（paragraph、table、row、cell；将来有 image、math、code 等）。
- role：主要语义类别（body、title、heading、caption、quote、code、list、reference、unclassified）。段落始终有一个 role。
- tags：用户自由标签，去空白、去重；标签不改变 Word 原有样式。
- context：表格内部、正文区域等，由结构推导，不靠标签猜测。
- source：原段落定位、样式名、分类依据、识别为建议还是用户确认。
- format：原始显示属性与本项目显式覆盖；不声称解析全部 Word 样式级联。

段落 ID 基于原 document.xml 的稳定遍历次序。阶段 1 不改内容结构，因此可稳定定位；后续内容编辑必须采用新的持久 ID 方案。

### 选择器

统一 JSON 表达条件树：all / any 组合，叶子包含字段、操作和值。首版 UI 提供全部满足/任一满足、角色、标签、表格位置、内容包含等条件，支持排除；API 模型允许嵌套组合。不执行用户提供的代码。

选择器由后端统一求值；页面高亮、预览、提交均依赖同一逻辑。空的 AND 为全部，空的 OR 为无匹配，UI 清楚显示匹配数量。

### 操作与撤销

- 类别/标签编辑和格式操作均是事务，可整体撤销/重做。
- 格式先预览后应用；预览展示命中段落与属性变化。
- 请求携带文档 revision，过期预览不得覆盖较新状态。
- 首版历史保留最近 50 次操作，随项目保存。更新通过临时文件原子替换；单个本地服务内串行写入。
- 保存的只是明确设置的属性，未设置属性保持原样。

### 格式适配

首版：中文/西文字体、绝对字号（磅与常见中文字号提示）、首行缩进（字符）、行距（倍数）、段前/段后（磅）、对齐。

段落属性写入选中段落 pPr；文字属性写入该段落所属的文字 runs 和段落默认 rPr。只覆盖明确指定字段，保留粗斜体、超链接、图片、公式等其他结构。首行缩进需处理 hanging 与字符/磅单位的冲突；字体需清理对应主题引用；字号写 sz 与 szCs；插入属性遵循 OOXML 顺序。

不修改样式定义，避免同一样式的未选中段落受到连带影响。标签/role 作为项目语义保存，首版不写进 Word 样式、不保证经外部 Word 编辑后继续映射原项目。

## 5. 界面结构

- 顶部：品牌、当前文件、保存状态、导入、保存项目、导出 Word。
- 左侧：常用选择器、类别统计、文档结构入口。
- 中央：结构阅读视图，段落旁显示类别与标签；命中高亮；表格显示独立上下文；点击对象检查/标注。
- 右侧「筛选与格式 / 对象」面板：组合条件、匹配数、分组属性、预览与应用；对象页修改角色与标签，查看原样式与格式来源。
- 底部：对象数、命中数、撤销/重做、状态提示。

提供有标题、普通正文、表格正文、带保护标签的正文、图注、代码的内置示例，可立即体验「正文 AND 不在表格 AND 无保留原格式标签」。

本阶段显示结构与近似排版，不是 Word 页面的精确重现。图片、公式、复杂域等保留导出，阅读视图以占位/提示说明；不能伪装成完整渲染。

## 6. 分阶段交付与验收门槛

### 阶段 1：可用的结构化格式工作台（本轮）

交付：
1. 计划、架构、参考调研、运行说明、状态记录；清晰的代码目录。
2. DOCX 导入，主体段落与表格投影，可见类别与标签，保守自动识别与手动纠正。
3. 组合筛选、高亮、对象检查、角色/标签标注。
4. 核心格式预览、应用、撤销/重做。
5. 自动本地保存、项目包导入/导出、生成独立的新 DOCX。
6. 内置示例、一键启动入口、核心回归测试、浏览器验证、Git 里程碑。

验收：
- 打开即可用示例验证，导入用户 DOCX 可重现流程。
- 正文首行缩进 2 字符时，标题、表格内段落和排除标签段落不受影响。
- 手工改类别与标签后筛选立即反映，撤销可还原，重开项目不丢状态。
- 预览明确指出影响范围；只有应用后更改项目。
- 导出原包的未处理 ZIP 项内容不变，未选中段落 XML 不变，文本内容不丢。
- 完成后停止，等待用户检查；不自行进入阶段 2。

### 阶段 2：持久规则与可解释格式

- 将选择器保存为命名集合，维护可复用规则模板。
- 一次操作与持续规则明确分开；规则顺序、冲突、局部覆盖来源可检查。
- 更完整的 Word 样式继承、混合 run 属性、字体主题、编号和分页属性读取。
- 中文字号递进、相对字号变化、批量标注、区域/章节范围、筛选嵌套 UI。
- 真实文件兼容性样本库与导出差异报告。

### 阶段 3：原生结构化写作

- 引入 ProseMirror/Tiptap，段落/标题/列表/表格/图片等编辑，Markdown 输入习惯。
- 持久节点 ID、版本迁移、原生项目格式及资源管理。
- 新内容自动匹配持续规则；内容操作与格式操作统一历史。
- 原生 DOCX 导出，导入时报告无法编辑或只能保留的对象。

### 阶段 4：复杂排版与分发

- 公式、引用、脚注、交叉引用、页眉页脚、分页与打印逐项扩展。
- Markdown/HTML/PDF 输出及属性降级报告。
- 根据用户反馈决定桌面封装、安装包及自动更新。
- Word 精确分页保持单独目标，不承诺浏览器与 Word 像素一致。

## 8. 风险和边界

- 自动分类依据样式名/大纲/编号等，必须显示来源；无法确定就未分类，不按字号盲猜。
- 主体普通段落与表格是首版操作范围；文本框、修订、内容控件等特殊区域视情况只保留，并给出限制提示。
- DOCX 的内容保留不等于版面不变；字号与行距变化本身就会引起 Word 重新分页。
- 不支持旧 .doc、加密文件或宏格式；导入有大小和解压上限，错误信息明确。
- 浏览器预览不能覆盖 Word 的字体替代、网格、复杂编号、条件表格样式和分页行为。
- 项目含原文件，属于本机资料；不提交 Git，不上传网络。服务器不向局域网开放。

## 9. Git 策略

1. 设计文档确认到可执行粒度后，初始化仓库并保存规划基线。
2. 阶段 1 核心实现及检查通过后保存可运行提交。
3. 后续每阶段单独保存，docs/STATUS.md 与实际代码同步。

下一位接手者先读 AGENTS.md、STATUS.md，再读本计划与架构。若用户提出新要求，以最新用户要求为准。
