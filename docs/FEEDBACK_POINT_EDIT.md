# F1 点选再收敛：持续增删、可编辑编号与稳定高亮

2026-10-21，基线 3a5ab87。用户明确纠正上一轮 Ctrl 手势分组：松开后继续操作同一项。本轮覆盖上一轮的分组/不可变快照设计，仍不进入模板 F2。

## 取舍与实现顺序

1. Ctrl/Meta 点击切换该段的实际选中状态，不按松开重新分组。无筛选时仍可普通点击换段；自定义筛选时普通点击只查看。增选合并到一个可安全复用的“点选 是”项，排除合并到“点选 不是”。若只由点选纳入，取消时直接从编号集合删除；同时被语义条件纳入时需要排除项。旧复杂表达式中并非同一逻辑位置的 ID 条件不能强制合并，避免改坏其含义。
2. 增选/取消必须在 all、any、NOT 和嵌套表达式中均真正生效。例如“正文 OR 标题”取消一段，不能简单 OR 一个“不是此段”，应成为“(正文 OR 标题) AND 不是此段”；在既有过滤外增选用 OR。必要时自动显示高级关系式，结果可见、可编辑。不增加持久 schema 或隐藏优先级。
3. 布尔组合调整放领域层，新增只读的 selection-adjust 接口，基于原筛选与一批点选意图生成现有 Selector 并统一求值；不写项目/历史。验证 revision、段落存在/可编辑、原条件有效以及条件/表达式上限。既有项目包和保存筛选仍用原格式。
4. 前端串行合并选择请求，保留上次有效高亮，Ctrl 点击只即时增删对应 ID；服务端返回后对齐实际结果。范围与版本签名同步禁用应用/保存筛选/批量标注，不能因保留旧高亮误提交旧范围；过期响应忽略，失败撤销临时高亮并显示错误。普通过滤输入更新也不再先清空整篇高亮。
5. 编号输入替换“x 段快照”，仅接受 ASCII 数字和空格，Enter/失焦完成后去重和去前导零；拒绝 0、过大编号、不存在或只读段落，不静默忽略。空输入留作待补全条件，不能隐式全选。输入草稿独立保存，未完成时暂停范围相关提交，跨工作页保留、离开文件受保护。
6. 删除编号折叠容器。悬浮/聚焦输入框显示完整编号，可滚动长列表；普通输入框可光标编辑。右键入口改为切换选择，键盘 Ctrl+Enter/空格保持同样含义。

## 验证与交付

后端验证组合真值、只增删指定段落、连续扩选不新增行、取消最后一个不全选、旧复杂条件不被改坏、范围/只读/revision/项目只读和导出保留。前端验证输入规范化、未知编号、连续操作合并、失效/过期结果、新鲜度与保留高亮；运行现有测试、Ruff 和构建。更新 STATUS/ISSUES/ARCHITECTURE/ACCEPTANCE 与 Git 后停下验收，不要求用户重做历史清单。浏览器仍受本会话已有明确策略拒绝，不能换方式绕过。
