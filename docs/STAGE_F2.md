# F2 类别模板：实施与恢复入口

2026-10-21。前置收尾提交 a4ea9fb。用户明确授权两个布局修复后直接继续本阶段；本阶段完成后暂停验收，不进入原生内容编辑。

## 产品契约

1. 用「模板」替换右侧「规则」。模板只包含类别及该类别的格式补丁，不保存段落、章节、标签筛选或持续绑定。应用一次，之后改类别不会重新排版；文档撤销可整笔恢复。
2. 模板保存在本机全局库，与文档项目分离，可导入/导出独立 JSON 文件。名称不重名；删除提供撤回入口。应用后的文档独立于模板库，删除模板不影响已应用格式；项目包携带结果而不自动污染其他机器的全局库。
3. 支持从空白新建、按类别编辑、从当前已保存文档提取。提取以整套已支持、可确定的属性组合作为统计单位；绝不逐属性拼凑众数。同类有差异时展示频次；最高频并列时先不选，用户明确选择候选后才能保存。可排除某一类别。
4. 文字属性只在同段全部文字 run 一致且已解析时提取；未知、混合、不能用现有字段/单位表达的值省略并解释。空段落参与统计但使用段落格式。模板显式设置某文字属性会统一该段的该属性；未设置的属性保留。应用预览提示会覆盖的混合文字属性。
5. 本阶段按现有九类匹配，所有小标题仍属同一类。多级标题/列表独立手工类别另行交付；模板结构版本化，为未来迁移留入口，不谎称已支持级别编辑。
6. 应用默认作用于全文中模板包含的类别；可选择「当前筛选」限定范围，便于排除特殊标签或表格。范围含义始终可见，未启用/未确认筛选不能应用该范围。模板编辑/范围变化自动预览，只有当前版本、模板内容、范围完全匹配的预览才能应用。
7. 编辑与应用是两件事：保存模板不更改文档，应用不暗中保存草稿。复用折叠格式组；避免多窗口。编辑草稿跨面板保留，换文档/模板或离开页面保护实际未保存输入。

## 旧规则与历史

打开旧项目或导入旧包时，将当前状态与每个 undo/redo 快照分别投影：按该状态的类别、标签和规则顺序计算有效补丁，再固化到各段局部覆盖，保留已有逐 run 字号、语义标注及命名筛选；之后清空活动规则。禁用/失效规则不产生格式。这样撤销仍恢复当时显示结果，不重新启动规则。

迁移前的完整当前状态、undo/redo 和规则作为结构化档案保存在项目里，随 .sdoc 携带。迁移统一升至 v5，原 DOCX 不动；成功完成全部状态的计算与校验后才原子写入，修订递增以拒绝旧页面提交。失败时不落盘。规则引擎和旧端点保留为兼容层及迁移验证基础，新界面没有持续规则入口；正常重新打开时再次检查兼容调用产生的旧规则。

## 模块与实施顺序

- 领域层：`domain/templates.py` 定义模板边界、提取、按类别生成候选 annotations；`domain/migrations.py` 负责旧状态冻结，均不依赖 HTTP/文件/XML。
- 存储层：`template_store.py` 原子保存全局模板库（版本与并发修订）；ProjectStore 协调迁移、模板预览/应用；DOCX 导出继续复用原 writer 与 audit。
- HTTP：模板库列表、保存/删除/恢复及导入导出；项目提取、模板预览/应用。请求含项目 revision，模板操作传完整冻结内容；库修改另含库 revision。
- 前端：模板页、纯草稿工具、串行即时预览 hook；App 管理跨页草稿保护及预览范围。原单次操作和点选不改语义。
- 自动验证：整套众数/并列、未知和混合省略、跨文档匹配、作用域外 XML 不改、一次应用及撤销/包重开、库冲突/删除恢复、旧规则优先级及全部历史冻结、前端过期预览不能提交。最后运行完整回归、Ruff、生产构建，更新文档并提交。

## 验证边界

浏览器若可访问则检查实际布局和模板交互；若权限层再次拒绝，不换工具绕过。已有自动回归不能替代视觉和帧率实测。环境失败针对性重试一次后交流。不得提交 data、用户文件或构建产物。
