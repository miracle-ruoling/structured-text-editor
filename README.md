# 文序 · 结构化文档工作台

让每段文字拥有可见的类别和标签，再按明确的范围调整格式。

当前是**阶段 1：DOCX 结构标注与批量格式工作台**。支持已有 Word 文档的导入、分类、标签、组合筛选、格式预览、应用、撤销/重做、项目保存与 DOCX 导出。正文内容编辑、持续样式规则和精确分页属于后续阶段。

## 现在开始使用

本机依赖已安装，前端已构建。双击根目录的 **`Start.cmd`**，将自动打开：

**http://127.0.0.1:8765**

保持启动窗口运行；关闭该窗口或按 Ctrl+C 停止服务。应用仅监听本机地址，不依赖 Office、Pandoc 或云服务。

首次打开会载入示例；以后自动恢复上次文档。左侧「打开最近文档」可切换本地项目。建议使用桌面浏览器、至少 1100 像素宽的窗口。

### 试试你最关心的操作

1. 使用示例，点击左侧「正文 · 排除例外」。应匹配 **5 个段落**。
2. 右侧「段落」→ 点击「2 字符」→「预览修改」。
3. 查看中间的缩进效果、右侧的变化清单，再点击「应用到 5 个段落」。
4. 小标题、表格内正文和带「保留原格式」标签的段落不参与修改。
5. 点「撤销」可整体还原；「导出 Word」生成新 DOCX。

点击文档中的段落可查看对象属性，手工修改主要类别、添加或移除标签。保存标注后筛选结果随即更新。

## 保存与导出

- **自动保存到本机**：每次应用格式或保存标注后，状态立即写入项目内 `data/`。预览和未保存的标注草稿不会写入。
- **保存项目包**：生成 `.sdoc`，包含原 DOCX、类别/标签、格式覆盖与最近 50 次撤销历史。可通过「导入文件」重新打开，也可以拷贝到另一台安装文序的电脑。
- **导出 Word**：生成新的 `_文序.docx`。不会覆盖原文件。类别与标签保存在项目中，不转换为 Word 样式。
- 浏览器下载由浏览器管理，通常位于「下载」目录。

请保留 `data/` 或导出的 `.sdoc`，不要把它们当作构建缓存清理。

## 首版边界

- 支持常规 `.docx`，不支持旧 `.doc`、Strict OOXML、加密文件和带宏文档。上传最大 30 MB，解压最大 100 MB，主体最多 20,000 段。
- 修改范围是文档主体内的普通段落和表格段落。内容控件、修订等复杂结构中的段落仅供查看。文本框、页眉页脚、脚注与尾注保留但不参与修改。
- 图片、公式、域和嵌入对象暂用提示占位；导出保留原始对象。
- 这是结构阅读视图，**不是 Word 页面复刻**。纵向合并表格分行显示；浏览器和 Word 的字体替代、行距、分页可能不同。
- 类别自动识别是建议，依据样式、大纲或编号。无法识别就显示「未分类」，可手动确认。
- 源文件与标签通过内部段落定位关联。不要直接替换 `data/` 中的源文件；在 Word 中改变内容结构后应重新导入为新项目。
- 目前为一次性批量操作；长期自动生效的样式规则在阶段 2 实现。

## 重新安装 / 开发

需要 Python 3.13、uv、Node.js 22（当前使用 22.21）和 npm。

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

该命令仅对当前 PowerShell 进程设置脚本执行策略，不修改系统策略。脚本使用 uv 创建 `.venv`，执行 `npm ci` 并构建前端；任何一步失败即停止。

手动命令：

```powershell
uv sync --cache-dir .uv-cache --system-certs
cd frontend
npm ci --cache ../.npm-cache --no-audit --no-fund
npm run build
cd ..
.venv\Scripts\python.exe -m structured_editor
```

开发前端：先运行 `.venv\Scripts\python.exe -m structured_editor --no-browser`，再在另一个终端进入 `frontend` 执行 `npm run dev`。Vite 会将 API 请求转发到本机后端。

可以用 `--port 8766` 修改正式服务端口，或用 `--data-dir 路径` 指定项目存储目录。开发代理默认指向 8765。

## 验证

在根目录：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check backend tests
```

前端目录：`npm run build` 同时进行 TypeScript 检查与生产构建。
