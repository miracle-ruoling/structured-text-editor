# 文序 · 结构化文档工作台

让每段文字拥有可见的类别和标签，再按明确的范围调整格式。

当前已完成**2C 反馈 F1 补充修正：持续点选与可编辑段落编号**，等待本轮验收。支持已有 Word 文档的分类与标签、高级逻辑筛选、直接点选及命名筛选、单次格式修改、持续规则、格式来源解释、批量标注、撤销/重做与 DOCX 导出。正文内容编辑与精确分页属于后续阶段。

## 现在开始使用

本机依赖已安装，前端已构建。双击根目录的 **`Start.cmd`**，将自动打开：

**http://127.0.0.1:8765**

保持启动窗口运行；关闭该窗口或按 Ctrl+C 停止服务。应用仅监听本机地址，不依赖 Office、Pandoc 或云服务。

首次没有本地项目时载入示例；以后自动恢复上次文档（浏览器未记住时打开最近项目）。打开文档默认处于「未筛选」状态。左侧「打开最近文档」可切换本地项目。建议使用桌面浏览器、至少 1100 像素宽的窗口。

### 试试你最关心的操作

1. 使用示例，点击左侧「正文 · 排除例外」。应匹配 **5 个段落**。
2. 右侧展开「段落」，点击「2 字符」，页面自动预览。
3. 在原位置查看蓝色未应用结果；需要时点「对照原文」。确认效果后点击「应用到 5 段」。
4. 小标题、表格内正文和带「保留原格式」标签的段落不参与修改。
5. 点「撤销」可整体还原；「导出 Word」生成新 DOCX。

未筛选时点击段落直接进入「操作」，普通点击换段，Ctrl 点击在同一组内增删。自定义筛选时普通点击只移动灰色查看框、不跳页；绿色匹配和蓝色预览优先。右键「检查对象」或打开对象属性页，可修改类别和标签。类别选择立即保存，标签按 Enter/+ 添加并保存，× 移除并保存；均可撤销。

自动类别识别正确时直接使用，无需确认。来源信息只说明类别如何得到；手动改过的类别可点「恢复自动识别」。对象页的「仅调整此段的格式」会把操作范围设为该段，使用同一个预览和应用流程。

### 高级与常用筛选

- 选择范围旁的 `{}` 开关开启高级模式，表达式输入位于条件列表后；用稳定代号构造 `$A AND ($B OR NOT $C)`。AND 表示同时满足，OR 表示任一满足，NOT 表示排除。条件值里的字母或符号不参与表达式解析。删除被引用条件会报错，不能继续应用。
- 主动编辑条件、选择预设或恢复筛选后进入自定义筛选。Ctrl/Meta 点击切换该段的实际命中状态，跨次点击持续复用“点选 是/不是”项；必要时自动显示 AND/OR 关系。右键「切换此段选择」效果相同。编号输入可直接编辑，数字以空格分隔，回车/失焦去重校验，悬浮显示完整编号。
- 右侧展开「保存此筛选」后为当前筛选命名，按 Enter 或保存图标后出现在左侧，可恢复和删除；删除可撤销。保存条件不保存格式、不自动改文档，每个项目最多 50 个。

### 持续规则和批量标注

产品方向将改为按类别匹配、一次应用的模板（F2），并迁移旧规则。本轮保留现有规则功能与数据，模板尚未实现。

先在操作页选范围，切到「规则」页创建规则，命名并设置格式，预览后保存。规则的文字/段落分组设置一起保存，与单次格式草稿独立。类别、标签变化后会重新匹配；列表可启停、移动和删除，均可撤销。

优先级为原文档 → 从上到下的规则 → 局部覆盖。对象页可展开各属性的来源层，并清除项目局部覆盖以使用下层格式。右键段落可快速检查、调整此段格式或切换此段选择。

操作页「批量标注」可以给当前筛选一次性增删标签、设置/恢复类别。它只操作提交前的命中，保留无关标注与格式。规则限当前项目，随项目包携带。

### 字号变换与结构范围

文字分组的字号输入框可统一设置磅数，两个 A 按钮按中文级数增减各文字片段。未填绝对值时累计本次净级数，连续 +、+、− 表示相对原格式 +1；输入绝对值后按钮调整该统一值。修改自动预览，未知/越界拒绝；应用后保存局部结果并清空草稿。对象页清除局部字号可恢复下层。

文字分组可设粗体/斜体；段落分组展开「分页与连排」可设置四个分页开关，空草稿显示当前开启/关闭、混合或未解析；选择开启/关闭才加入本次修改。它们也可用于现有规则；浏览器不模拟 Word 精确分页。预览会提示前段连排与后段分页的相邻冲突，不强制改值。

筛选字段可选「章节」「Word 分节」。左侧折叠章节入口选择该标题及全部子章节，表格内标题不切断外层章节。对象页可查看章节路径、原大纲、分节、编号。标题改类后章节重新划分；引用已消失章节的筛选报错，规则暂停匹配并说明，防止否定范围意外扩大。

## 保存与导出

- **自动保存到本机**：每次应用格式、更改标注、保存/删除命名筛选或修改规则后，状态立即写入项目内 `data/`。预览与未提交草稿不会写入。
- **导出项目包**：生成 `.sdoc`，包含原 DOCX、类别/标签、格式覆盖、命名筛选、持续规则与最近 50 次撤销历史。可通过「导入文件」重新打开，也可以拷贝到另一台安装当前版本文序的电脑。当前 v4 格式兼容读入旧 v1/v2/v3 项目；旧版程序不能读取新包。
- **导出检查**：可选查看实际 Word 输出与原文件的差异，包括变化段落与属性、内容和范围保留结果、兼容性边界；可下载带修订号和文件散列的 JSON 报告。只包含已保存状态。
- **导出 Word**：生成新的 `_文序.docx`。不会覆盖原文件。类别、标签及规则定义保存在项目中，不转换为 Word 样式；Word 导出的是当前规则和局部覆盖共同计算的结果。每次自动检查范围和内容保留，发现非预期变化会拒绝导出。
- 浏览器下载由浏览器管理，通常位于「下载」目录，下载重名时加副本编号；导出不会新增本地项目或修订。后续桌面封装可以提供选择路径和覆盖保存，目前导出保留浏览器下载方式。
- 重复导入完全相同的 DOCX 会打开最近本地项目；相同项目快照复用现有项目，不同快照作为名称可区分的独立项目。旧同名项目不删除，最近列表显示日期、修订号和短 ID。

请保留 `data/` 或导出的 `.sdoc`，不要把它们当作构建缓存清理。

## 筛选、预览与草稿

- 未筛选时只显示空闲提示及新建/恢复入口，不展示条件。退出清空当前范围并保留同文档恢复快照，保持原工作页签；首次进入或切换文档没有上次记录。简单模式删除最后一个条件不会自动全选，全选请点「全部内容」。
- 修改格式后约 180ms 合并输入并自动预览；未更新完或有错误不能应用。可切换原文对照，预览不保存、不增加历史。
- 文字/段落可折叠，所有填写属性一起应用。分组显示待应用项数，底部完整摘要可逐项取消；折叠不改变提交范围。
- 应用成功清空全部格式草稿，无锁定选项。取消修改/Esc 清空草稿并恢复已保存视图；已应用的修改用撤销还原。对话框优先处理 Esc。
- 切换文档时，已保存内容不重复询问；仅未应用格式、未添加标签、预览等会丢失时提示。切换工作页保留但暂停单次草稿预览；成功切换文档清空草稿。

## 首版边界

- 支持常规 `.docx`，不支持旧 `.doc`、Strict OOXML、加密文件和带宏文档。上传最大 30 MB，解压最大 100 MB，主体最多 20,000 段。
- 修改范围是文档主体内的普通段落和表格段落。内容控件、修订等复杂结构中的段落仅供查看。文本框、页眉页脚、脚注与尾注保留但不参与修改。
- 图片、公式、域和嵌入对象暂用提示占位；导出保留原始对象。
- 这是结构阅读视图，**不是 Word 页面复刻**。纵向合并表格分行显示；浏览器和 Word 的字体替代、行距、分页可能不同。
- 类别依据样式、大纲或编号自动识别。无法识别就显示「未分类」，可手动更改；不需要确认识别正确的类别。
- 源文件与标签通过内部段落定位关联。不要直接替换 `data/` 中的源文件；在 Word 中改变内容结构后应重新导入为新项目。
- 支持单次格式操作与持续规则；命名筛选仅复用条件，持续规则还保存格式并自动匹配。按类别的一次性模板（F2）尚未实现。

## 重新安装 / 开发

需要 Python 3.13、uv、Node.js 22（当前使用 22.21）和 npm。

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

该命令仅对当前 PowerShell 进程设置脚本执行策略，不修改系统策略。脚本使用 uv 创建 `.venv`，执行 `npm ci` 并构建前端；任何一步失败即停止。

手动命令：

```powershell
uv sync --cache-dir .uv-cache --system-certs
cd frontend
npm ci --cache ../.npm-cache --no-audit --no-fund
npm run build
cd ..
.venv\Scripts\python.exe -m structured_editor
```

开发前端：先运行 `.venv\Scripts\python.exe -m structured_editor --no-browser`，再在另一个终端进入 `frontend` 执行 `npm run dev`。Vite 会将 API 请求转发到本机后端。

可以用 `--port 8766` 修改正式服务端口，或用 `--data-dir 路径` 指定项目存储目录。开发代理默认指向 8765。

## 验证

在根目录：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check backend tests
```

前端目录：`npm test` 检查选择范围、字号草稿、异步预览竞态、真实组件静态输出与缩进计算；`npm run build` 同时进行 TypeScript 检查与生产构建。

当前结果：后端 92 项、前端 39 项（含静态组件输出）、Ruff 和 TypeScript/Vite 构建通过。用户已通过阶段 1、2A 和 2B，本轮交付 F1 补充修正后暂停。浏览器工具此前被已保存权限/管理策略阻止，未完成实际点击验证；用户仅需查看[本次变化](docs/ACCEPTANCE.md)，不重做历史回归清单。

长文档基准：`.venv/Scripts/python.exe scripts/benchmark_preview.py --paragraphs 5000`。结果写入忽略目录；它只测后端计算和序列化，不代表浏览器帧率。
